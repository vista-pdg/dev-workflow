Las pruebas locales del código publicado pasaron (397 backend, 105 unitarias frontend y 47
Cypress por navegador). Los primeros checks remotos de calidad también aprobaron. Los cuatro
jobs E2E remotos abortaron antes de ejecutar un spec de Cypress con el mensaje

El workflow compartido de main aún usaba `cypress-io/github-action@v6`, ejecutado por GitHub
con Node 24. El mensaje y la terminación inmediata de su sondeo coinciden con el
[problema oficial #1873](https://github.com/cypress-io/github-action/issues/1873).
La [documentación oficial](https://github.com/cypress-io/github-action#compatibility) recomienda
v7, compatible con Cypress 10 o posterior y ejecutada en Node 24. El problema de reintento del
sondeo se corrigió en la línea v7; se usa HTTP local, sin certificados autofirmados.

Se actualizó una línea del workflow compartido a `cypress-io/github-action@v7`, commit
`3bce988eaac695732a20f66b83bd8471e61d1e47`. Backend y frontend fijan su llamada reutilizable a
ese SHA para probar el arreglo antes de integrar main y conservar una referencia válida aunque
se retire la rama de publicación. Se mantienen los mismos navegadores, specs, perfiles e2e,
cuotas de prueba y requisitos de éxito.

Las tres configuraciones YAML se parsearon y se comprobó el destino de `jobs.e2e.uses`. Antes
de cada push se ejecutó otro fetch, se comprobó que el padre coincidiera con el remoto y se
verificó el SHA publicado con `git ls-remote`; sin force-push.
